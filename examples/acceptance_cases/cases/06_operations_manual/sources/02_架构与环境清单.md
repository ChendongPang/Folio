# 当前架构、服务和权限范围

## 服务拓扑

用户流量经gateway进入api；api调用PostgreSQL保存任务和权限，调用Redis保存缓存，并将导出任务写入Redis队列；worker消费导出队列，将产物写入对象存储，再更新任务状态。附件直接进入对象存储，数据库保存对象键与元数据。
prod-sim中gateway为2副本、api为3副本、worker为2副本。PostgreSQL为1主1备；Redis为单主实例，故障切换机制尚未提供。对象存储使用独立存储桶team-files-sim，名称为虚构标识。预发不宣称同等容量或高可用。

## 部署与可观察性

生产命名空间为team-prod-sim，预发命名空间team-stage-sim。工作负载标签分别为app=gateway、app=api、app=worker。监控每60秒抓取一次；访问日志、应用日志和审计日志集中保存14天。
可观察性字段包括request_id、task_id、service、version、status_code、duration_ms；跨服务排查应优先关联request_id，异步导出使用task_id。日志不得包含访问令牌和用户附件正文。
只读示例可使用kubectl -n <namespace> get pods -l app=api或kubectl -n <namespace> logs <pod> --since=10m。所有尖括号为待替换占位，案例不能执行示例命令；未提供真实集群入口或凭据。

## 数据保护事实

数据库每天02:00 Asia/Shanghai执行加密全量备份，保留7天，备份作业记录位置以实际平台为准。没有提供WAL归档、连续恢复或跨地域复制的批准资料，因此不能推断可恢复到任意时间点。
对象存储开启版本保留，保留周期未提供；附件与数据库一致恢复的校验方案待制定。最近一次全流程恢复演练日期和结果没有材料，不能宣称备份已经验证可恢复。
