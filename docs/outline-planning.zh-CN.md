# LLM 目录规划设计

> English version: [English version](outline-planning.md)

以写作要求与资料规划目录，支持可选的用户 DOCX 模板和按需联网补充；旧版强制模板流程、伪大纲和大纲引用协议已删除。

## 输入与流程

GUI 上传文件并提交写作要求，文件默认是普通资料 `source`，可以明确指定一份 DOCX 为文档模板 `template`。CLI 使用 `--request` 或 `--request-file` 与 `--knowledge`；作业 API 使用 `user_request`、`knowledge_path` 或已有知识库配置。旧版公开输入中的 `template_path`、`outline_path` 参数不恢复，不创建伪装成大纲的 `outline.md`，也不为用户要求分配 `o1` 等引用编号。可选模板从工作台文件用途进入，可信模板约束随文档计划传递。

成品范文可明确设为 `style_reference`。目录规划前，程序对风格示例统计结构、正文与排版，主模型按请求容量分批读取全部可提取文字并归纳写法，生成 `style/style.md` 及同源 `style/profile.json`。原件单独保存在 `style-references/`，不会进入业务研究 Manifest 或原文证据；主范文的结构组织与标题习惯以精简 Markdown 传入规划上下文。范文中的具体标题、业务规则和章节数量不能提升为本次要求。缺乏风格样本不等于缺乏业务资料，不借风格分析绕过来源研究。

风格分析受 `StyleAnalysisConfig`、实际容量和目录调用总额度共同限制，不再以三次抽样代表完成全文分析；文字覆盖与需要页面图像的视觉缺项分别记录，具体上限见[请求上下文与容量设计](context-and-capacity.zh-CN.md)。角色、文件哈希和风格参数随确认版本冻结。`SourceDirectoryDrafts.load` 返回同版 `sample_paths` 与 `writing_profile`，`Store.create(..., writing_profile=...)` 校验并冻结到作业；正文复用该结果，不在各章重复提取风格。

目录流程为：写作要求与文件快照 → 普通资料的共享索引，以及可选模板约束提取 → 主 LLM 浏览 Manifest，选择相关文件并按需查看内部结构、读取原文与补读 → 提取带原文依据的目录要求及尚未解决的问题 → 完整 `plan` 模型请求 → 结构、模板约束与来源要求去向检查 → Word 版式预览 → 研究充分且检查通过后，用户确认当前目录版本 → 业务任务规划与正文研究写作。无模板时采用已确认的风格排版参数并由内置规则补足；有模板时预览与正文均以冻结的原 DOCX 为基础。

`planning_context(requirements, source_catalog)` 仍提供完整写作要求和资料导航，研究结果另作为规划依据传入。目录生成前的研究入口使用共享 SourceIndex 和现有文件工具，让主 LLM 根据目标选择文件、浏览标题／Sheet／真实 PDF 书签、读取相关原文、搜索和继续翻页；不再固定截取每份资料前 8 个标题、前 12,000 个字符后直接规划。清单和结构只是导航，程序完成解析不等于模型已读原文，搜索命中也不等于已读完相关范围。研究工具返回截断、下一页和未读状态，模型需要继续读取或明确保留缺口。

上传校验后，每份原件旁保存由程序生成的 `structure.json` 与 `structure.md`。建立目录资料快照时，`SourceIndex` 复用共享解析对象，生成 `structures/<file_id>.json` 和对应 `.md`；JSON 保留精确定位及版本，Markdown 只描述真实内部结构。`fs.inspect` 直接提供该 Markdown，正常大小一次完整返回，极大结构才按完整节点分页。Word／Markdown 保留标题层级，Excel 保留 Sheet、范围和表头候选，PDF 使用真实书签或紧凑页码范围，PPT 使用幻灯片标题。解析状态在相关正文读取结果中说明，不混入结构文件。

模型通过文件、`F1/N005` 等节点定位或页码读取资料，原始路径、节点 ID、来源版本及证据引用仍由后台核对。研究输入以文本／Markdown 组织，工具动作通过原生 `tool_calls` 调用 `fs_read` 等函数；程序以匹配的 `tool_call_id` 回传真实结果，不从回复文本解析动作 JSON。研究结束通过原生 `finish` 提交结论，其中 `requirements` 使用 `E1` 等证据编号引用已读原文；所选范围 `selected_ranges` 由程序从证据和真实阅读记录推导，模型不再填写范围编号。后台继续检查要求、原文依据、实际交付和未解决问题，不向每轮资料上下文重复嵌入完整 `finish_contract`。可以引用已读的一页，不强制读完其所在的整个查询范围；范围的 `complete=false` 与未读摘要仍按实保留，不能将局部依据冒充全章覆盖。

`fs.inspect` 是推荐的导航工具，不要求每个选用文件都先完整浏览结构。通过搜索、明确页码或节点定位读到正文后，只要相应证据真实、版本一致且已完整发送，就不会仅因没有调用 `fs.inspect` 阻塞结论。结构查看记录仍按实际执行情况保留；省略导航不等于已经浏览结构，也不会让搜索摘要或未发送内容变成已读原文。

一次研究回复可包含最多16个工具调用，流式接收会完整拼接每个调用，再校验并执行；独立的文件工具最多4个并发。下一次请求保留这一批完整的 `assistant.tool_calls` 及各自带 `tool_call_id` 的结果，文件证据、阅读进度和短编号按调用顺序登记。需要前一步结果的读取必须放到下一轮请求；`finish` 必须单独调用，混批时整批返回错误，不能凭尚未发送给模型的结果宣告研究完成。模型调用与工具操作分开计数：目录研究默认最多36次模型调用、3轮研究和120次工具操作；并发读取前按批预留原文额度，不让每个工具重复使用全部剩余额度。

目录研究按完整请求检查容量，包含系统消息、资料文本、原生调用记录、全量笔记和工具定义。Runtime 默认输入预算为 600,000 Token，输出默认 128,000 Token，兼容旧输入配置缺失/null，切换模型不回退到旧的字符限制。服务不能计数时明确标记本地估算，已知总窗口更小时按实际窗口限制。单次正文读取仍可分页，分页大小不代表整个研究历史的上限；累计原文字数额度 `max_evidence_chars` 默认留空，仅在显式配置时限制累计读取量。工具实际提取和实际交付的范围分别记录；未发送的尾部不能标为已读。`finish` 只能引用实际提供的原文。详见[请求上下文与容量设计](context-and-capacity.zh-CN.md#输入与输出分别管理)。

文件短编号、内部路径和唯一展示文件名均可用于读取；同名歧义时返回候选短编号。续读编号已经包含定位，重复传入相同文件或相同位置可接受，冲突定位才拒绝。常驻阅读进度显示可直接执行的续读入口。相同证据跨批次出现时，按证据编号、来源、版本及位置同时继承交付和归纳状态，避免只记住“已归纳”却又要求重复发送。

工具错误、连续无进展或达到预算时先保存成果；有已交付原文、剩余调用和时间时，最多追加一次仅允许 `finish` 的收尾请求，计入原有预算。正常读取为收尾预留一次调用及部分原时间额度；用户取消、模型超时或不可用时不继续发起收尾模型请求。收尾仍校验真实交付、范围、引用和未完成事项，不能用空结论放行。报告增加 `termination_reason`、`failure`、`conclusion_submitted`、`finalization_attempted`、`working_findings`，后者保留有实际交付依据的笔记，推断不会变成已确认事实。

目录规划接收正式要求、有效研究笔记及相关已交付原文；研究未完成时保留已交付材料，不因缺少 `finish` 而丢掉研究成果。覆盖检查区分研究未完成、工具/模型执行失败、真实资料缺口、目录遗漏和审查容量不足。只有研究已经就绪、目录确实遗漏要求时才重试目录生成；上游研究失败不能通过反复改写目录修复。`confirmation_issues` 随目录版本保存并传到界面，显示具体阻塞原因。

目录研究与业务研究共用 `ResearchMemory`：程序记录真实交付范围，模型在下一次工具调用附带 `research_notes` 增量，将发现、任务影响、原文引用及未解问题按条累积。笔记使用 `evidence_ids`，不再要求 `request_ids`；请求批次关联由程序核对实际交付记录。省略笔记不清空旧内容，指定 `note_id` 才修订已有条目，重试不会重复追加。每批原文移出当前上下文前须留下归纳；没有相关发现时可提交 `no_relevance`，不能仅因未找到结论就反复读取同一范围。待归纳状态只限制原文能否压缩，不因读过但未采用的证据尚无笔记阻塞 `finish`，也不要求为结束研究逐条补写无关说明。研究笔记持久保存在报告并导出 `research.md`，详细契约见[共享研究记忆](agent-research.zh-CN.md#共享研究记忆)。

正常请求保留本次研究的完整工具历史、全量笔记与待核实问题；清单和结构结果不会因为已经发送过就自动退出上下文。完整请求超出模型输入容量后才缩减历史，已归纳的旧原文可优先退出；仍超限时再将笔记换成可分页读取的索引。后台完整记录始终保留，历史入口标明文件、页段和证据，不以裸编号要求模型猜测。复读已读范围须说明具体核实原因，连续无新增证据、有效笔记或缺口进展时按原有预算保留未完成状态。研究完成以足够支持当前目录为准，不要求所有原文同时留在最终上下文，也不把模型推断升级为全局事实。

研究有工具、调用、时间和上下文预算，不要求无条件通读全部附件，也不按固定领域词强制选择章节。影响目录的关键依据不足、预算用尽仍未提交有效结论、相关资料无法解析或用户范围尚未确定时，研究报告保持 `partial`；可展示初稿和具体缺口，但不能确认后直接进入正文。没有普通资料时记录 `no_sources`，允许按用户要求与可选模板规划，不伪造阅读记录。目录研究报告与读取记录保存原始文件版本、定位、证据和要求编号；这些是实际来源要求，不是已删除的伪大纲。

选择模板时增加 `template` 上下文，仅包含真实固定章节、填写说明、允许扩展的位置和必填表格表头，不提供示例业务正文、数据行或本地文件路径。模板不进入普通资料的 `source_catalog` 或研究目录；与模板内容完全相同的重复资料会在规划前报错，避免样例被重新当作事实。

完整目录提案不分批，也不按固定业务词预分组；资料阅读和来源要求审阅可以分页／分批。无模板时，模型决定章节标题、层级、顺序、写作说明与容器关系；有模板时，模型保留模板固定结构，只在明确允许的位置扩展章节。写作指南随目录请求一起提供，但它不是业务证据，不新增指南专用审阅调用。超出规划输入预算时明确报错，不暗中截断写作要求或改成固定规则目录。

## 按需联网补充

目录研究仍由同一个 Agent 决策，先理解用户要求和相关上传资料。模型配置中的搜索服务（Tavily 或 DeepSeek Search）已启用且验证通过时，提供原生 `search_web(query, purpose, summary)` 工具。只有具体公开问题会影响目录范围或章节安排时才搜索；资料已经足够时直接完成本地研究，不新增固定搜索阶段。用户要求不联网时遵守该要求。缺失的投标人信息、报价、人员证书等私人材料保留待补，不能靠搜索填造，也不发送敏感原文作为查询。

工具返回带 `W` 引用、URL、标题和获取时间的公开网页摘录，明确不是已核验的网页全文或项目事实。模型在 `finish.web_findings` 中单独归纳它们，上传资料要求仍只能引用 `E` 原文。公开参考不会覆盖招标文件、模板约束，也不能代替本地文件覆盖检查。程序检查公开引用真实存在且摘录已发送给模型，不把来源身份校验等同于内容真实性验证。

联网与文件工具共用当前研究的时间、工具数、模型调用数和上下文预算，最多四个工具同时执行；不额外设置固定搜索轮数。相同标准化查询复用本次研究目录保存的结果。失败会保存状态和安全错误码，保留已有资料，由模型决定记录缺口或在原预算内重试。结果超出当前请求容量才分页，全文仍保留，并通过 `fs_read(scope='history', request_id=..., offset=...)` 续读；未显示摘录不能引用为已读。

`research/web-research.json` 保存查询、用途、结果状态、来源摘录与结论；`research/report.json` 的独立 `web_research` 字段汇总这些记录。界面沿用原进度框显示搜索目的与结果，并在资料研究记录中展示来源链接。目录规划接收公开参考，确认后随目录研究冻结到正文作业。业务 Agent 得到已查问题、结论和来源导航，完整摘录进入其证据池，可本地读取复核；只有新问题或确有必要的时效核对才需要再搜。这些结论不自动成为全局事实。没有配置搜索服务时，目录本地研究保持可用。

## 数据契约

`PlanProposal` 只有 `sections` 与 `notes`。每个 `PlanItem` 包含：

- `node_id`：目录节点稳定标识，用于局部修订和章节身份。
- `title`、`level`：标题和层级。
- `instruction`：本章写作要求。
- `content_mode`：`generate` 需要正文，`container` 仅组织子章节。

模型输出不包含旧版 `outline_refs`、`mapping_reason`、模板栏目／表格引用或未使用模板栏目清单。`build_plan(document_id, proposal, template=...)` 计算稳定 `section_id`、父子关系、章节路径和显示编号；`Section.node_id` 表示生成目录节点，不声称对应原资料。

有模板时，程序用可信的 `TemplateContract` 校验并绑定计划：`DocumentPlan.template` 保存冻结原件路径、哈希与结构约束；`Section.template_section_id` 关联真实模板章节，`required_tables` 保存必填表格约束，`allow_subheadings` 控制正文中的下级标题。上述字段由程序派生，不由 `PlanProposal` 自行声明或删除。这与已经移除的强制模板栏目匹配协议不同，不要求无模板任务提供虚构映射。

业务来源仍使用独立的 Evidence、`source_id`、locator、`evidence_ids` 和研究记录。删除伪大纲引用不影响事实溯源、共享事实、研究覆盖清单或正文引用核验。

## 校验边界

代码检查 JSON/schema、必填字段、唯一节点 ID、非空标题、从一级开始且不得跳级、同父级标题重复、正文节点的写作说明、容器必须有子节点。目录修改后重新检查完整结果。

不做大纲编号存在性或原大纲覆盖检查。明确选择模板时，额外校验固定标题、层级、父子关系和顺序，以及新增章节是否位于允许扩展的位置；含必填表格的章节必须生成正文。默认不扩展模板章节，可通过模板中的明确填写说明开放子章节，具体规则见[用户模板设计](templates.zh-CN.md)。

`review_directory_research` 使用主模型，将研究得到的每项 `requirement_id`、对应完整原文证据与整份目录对照，返回 `covered`、`not_applicable` 或 `missing`。覆盖必须明确落到实际生成正文的节点标题或写作说明；多个要求可以共用一个章节，不要求一条要求一个章节。排除项必须说明用户范围或原文适用条件，尚未选定投标包件不能作为自行排除的理由。程序检查每项恰好一次、真实 `node_id`、该项真实 `evidence_ids`、非空理由，拒绝伪造 ID、漏项和只指向容器。这个结果单独保存，不向 `PlanItem` 恢复 `outline_refs` 等字段。

覆盖审阅按预算打包全部要求及其原文，单批提供完整目录，原文不截断；默认最多 12 批，并受本次调用额度限制。单项完整上下文仍过长或全量审阅超过批次预算时明确返回缺口，不只检查前面的要求后宣布通过。模型失败、响应截断、缺项或非法引用不能算通过。发现遗漏后进行有界目录修复并重新检查，仍有缺口则保持不可确认的初稿。每批请求前落盘输入，收到响应后保存结果、用量和耗时，失败或取消也保留已经完成的批次。

来源要求去向检查通过，仅说明已经研究出的要求有明确目录安排；研究本身的 `partial`、范围未确定等问题仍会独立阻止确认。正文阶段继续做实际内容覆盖、原文引用、事实与一致性审阅，目录阶段不声称正文已经满足要求。

JSON 无法解析或 schema 不通过时，反馈错误与原始返回，要求模型重新输出完整目录；schema 有效而结构检查失败时，才允许只修改明确的错误路径，其余节点保持。无效的修复响应不会覆盖上一份 schema 有效的目录基准，后续修复继续基于该基准。完整目录重新校验通过后才发布新预览。修正有调用次数、时间和输入预算限制；只有错误数量减少才可获得有限额外修正。传输错误不冒充目录结构错误，不因超时自动启动目录纠错。输出被截断不会作为有效目录。

模板固定结构错误可能需要补回整棵子树，因此没有安全局部修复路径时重试完整提案，不放宽模板约束。模板本身无法解析或包含暂不支持的结构时，明确提示修正原模板，不静默切换成自由生成。

## 修改、恢复与预览

`revise_plan` 使用稳定节点 ID 执行标题／说明更新、插入、移动和删除；移动会携带子树，避免按数组位置误改无关章节。有模板时，修改后的完整结果仍受固定结构及扩展边界约束，修改后的来源要求去向也重新检查。失败时保留上一个版本，但是否可确认仍取决于当前要求、资料版本、研究状态和检查结果。确认携带目录版本，并核对需求、写作指南、全部上传文件 ID 和 `source_roles: [{id, role}]`；旧版本确认或角色变化不能启动正文。历史元数据没有 `source_roles` 时，只兼容全部普通资料的目录。

生成预览写入 `previews` 并通过 `/previews/{id}`、PDF、页面图片和下载端点读取。不存在模板列表或推荐接口。旧磁盘预览可只读加载；旧作业与已保存目录在明确的持久化读取迁移层删除废弃字段，新的模型和 API 输入仍严格拒绝旧字段。

输出目录保留 `planning-input.json`、`planning-attempts.json`、`planning-proposal.json`、`document-plan.json`、`writing-guide.json` 和 Word 预览。目录前研究另存 `research/report.json` 与真实工具读取记录，来源去向审阅的逐批输入输出保存在 `research-review-attempt-*.json`。可选模板另存冻结的 `template.docx` 与 `template-contract.json`；风格示例另存 `style-references/`、`style/` 说明及分析记录。文件用途写入 `metadata.json` 的 `source_roles`，所有非事实原件与普通资料目录分离。

确认后通过 `Store.create(..., directory_research=...)` 将目录研究及审阅结果冻结到作业的 `inputs/directory-research/`。正文任务参考其中同版原文证据与自身目录节点对应的要求，仍按需要继续补读；研究摘要不自动提升为全局事实，也不跳过正文核验。正文作业另行复制模板并验证哈希，生成及最终交付检查其结构与格式未被改坏。调用记录包含耗时、用量和错误诊断；解析、绑定和程序结构校验不增加模型请求，目录研究与语义覆盖审阅会增加实际主模型调用。

CLI `generate` 和直接作业 API 在没有已确认计划、但提供本地资料或 DOCX 参考文件时，也先执行同一目录研究和去向审阅，再保存正式计划；`partial` 或覆盖修复失败不会进入正文。它们通过 `JobPlanningRuntime` 将模型动作转交 `Engine.call`，实际调用、格式重试和恢复都计入作业总账及持久阶段额度，不另走未记账的 Runtime 请求，也不为此生成额外 Word 预览。已有计划不重复目录研究；仅配置远程检索且没有本地资料时保留原远程检索边界，不声称已研究远程全文。
