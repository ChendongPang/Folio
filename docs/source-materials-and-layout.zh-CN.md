# 资料研究与 Word 排版设计

> English version: [English version](source-materials-and-layout.md)

以写作要求和资料为输入，工作台支持可选 DOCX 模板；不恢复旧版强制模板和伪大纲流程。

## 资料输入与事实边界

GUI 区分普通资料 `source`、文档模板 `template` 和风格示例 `style_reference`。普通资料和风格示例支持 DOCX、Markdown、TXT、XLSX、PDF、PPTX 及图片；模板每会话最多一份 DOCX，由用户在资料库明确指定。文件名含“模板”或“样例”不会自动改变用途。CLI 使用 `--request`／`--request-file`、本地资料目录或显式知识库配置，`--sample` 接入同一风格分析流程。风格示例先进行格式测量，再按实际请求容量分批读取全部可提取文字；页面图像分析另行记录实际查看范围，不因文字读完就声称已看完全部图片。预算、解析或模型错误造成的未完成部分保留为缺项。分析生成 `style.md` 与冻结的风格档案，供目录、正文、Word 排版及最终检查复用；示例原文只进入独立风格分析，不进入业务事实或证据。用户明确要求和模板优先于示例，无法可靠测量或确认的风格保留为未知。

资料首先固定为快照并建立共享 Manifest 和内部结构索引。Manifest 记录文件身份、类型、大小、哈希和预处理状态；结构索引保留标题、Sheet／表头／单元格、真实 PDF 书签或页码，以及 OCR、公式缓存和未读范围警告。资料源定位与最终文档章节身份分别维护。

模板原件单独冻结为 `template.docx`，提取结果写入 `template-contract.json`，全部上传文件的用途保存在目录元数据 `source_roles` 中。模板的固定章节、填写说明和表头用于输出约束，模板示例正文和数据行不进入普通资料目录、检索证据或全局事实。同内容模板重复标为普通资料时，规划前明确要求移除重复附件，聊天也不读取其样例正文。更换模板不自动把旧模板转为业务依据。

目录生成前，主 LLM 先浏览 Manifest，再自主选择文件、按需查看内部结构、定位并读取相关原文和继续翻页，形成带原文证据的目录要求与未解决问题。已有明确页码或节点定位时可以直接读取，不因省略结构浏览而单独阻塞研究结束。笔记和目录结论引用证据编号，批次与所选范围由程序根据真实交付记录关联，不要求模型维护内部请求或范围编号。已发送的页段可以作为依据，不强制读完其所在的整个查询范围；未读状态保持真实，不把局部引用冒充全文覆盖。文件少或已完成预处理不等于模型已经读过；不再用每份资料开头的固定摘录代替这一步。研究调用、工具和时间均有界，影响目录的关键依据不足、预算用尽仍未提交有效结论或包件／业务范围尚不明确时保留 `partial` 初稿，不能直接确认进入正文。

正文研究推荐按文件清单 → 内部结构 → 检索片段 → 对应完整范围逐步取证，允许根据已知定位直接读取。每轮允许有限工具动作，本地最多三轮，联网补查最多两轮；仍缺乏项目证据时可以补充模型建议，但不能将猜测写入已核实共享事实。目录前读取记录与同版原文证据可以作为后续任务的起点，不能把“读过某处”当成整份资料或完整正文已经通过核验。OCR 未经核实、未批准参数和未验证计算保留相应状态。

`reader.py` 继续读取 DOCX 标题、段落、表格、修订和批注。修订视图显式选择；搜索命中不能自动证明完整覆盖。批注与资料内容不会因为出现在某份样例中就自动成为用户需求。

## 目录与正文

无模板时，目录由写作要求和实际资料研究结果共同规划；有模板时，在保留其固定结构和明确扩展边界的前提下安排写作。两种流程都不创建伪大纲，不要求模型输出旧版来源映射理由。程序校验目录自身结构；选用模板时再校验固定标题、层级、父子关系、顺序和必填表格所属章节。

结构通过后，主模型按原文逐项核对研究要求是否在目录标题或写作说明中有明确去向。一项要求可由多个节点承担，多项要求可共用一个节点；不适用项要有明确范围依据，程序拒绝不存在的要求、证据或节点编号。遗漏触发有界修复，未修复、尚未完成研究或未确定范围的目录只作初稿，不能确认。详见[LLM 目录规划设计](outline-planning.zh-CN.md)。真实业务引用仍保存在 Evidence、定位信息与 trace 中；正文不显示内部 `ev_`、`sfref` 或运行器字段。

模板约束由程序绑定到已确认计划：`template_section_id` 关联模板章节，`required_tables` 定义必填表格，`allow_subheadings` 限制正文扩展标题。模型不能自行删除这些字段。正文阶段确定性检查表头、表格数量、数据行和禁止新增标题等要求，沿用现有修复及待确认交付机制；缺资料的字段应明确待确认，不用模板示例值补成事实。

确认后的目录进入业务任务 DAG。`Store.create(..., directory_research=...)` 将目录研究与去向审阅结果冻结到作业 `inputs/directory-research/`，正文任务只继承同版原文证据和对应节点要求，按业务问题继续补读。Business Agent 研究资料、参考全局事实、生成正文和所需配图；审阅器检查事实、完整性与一致性；协调器控制预算、依赖、提交和恢复。目录摘要不直接进入全局事实，模板样例始终与业务证据隔离；目录删除旧映射字段不改变这些协作边界。

## Word 版式与模板格式

唯一正文导出入口为 `render(target, plan, states, ...)`。无模板时，程序创建文档并安装内置中文／西文字体、标题、正文、表格和目录样式。有模板时，以冻结的原 DOCX 为基础填充正文，保留模板定义的样式、页面与分节设置、固定标题、页眉页脚和必填表格布局；正文参考对应章节的格式，未规定的新增内容采用默认规则。两种模式都不恢复旧版 `{{folio.content}}` 整块插入协议。

模板章节内的填写提示、示例正文和示例数据行会被本次内容替换；第一章节前的封面固定内容与图案保留，支持明确的文档标题占位符，不猜测所有旧项目封面值应该替换成什么。正文图片、内容控件、未处理修订等暂不能安全填写的结构会报错，完整支持范围见[用户模板设计](templates.zh-CN.md)。

通用规则包括标题层级和编号、稳定书签、可点击目录、页码域、正文列表缩进、表头重复、表格行不跨页、图片宽高限制、图题和连续图号；应用这些规则时，模板已经明确规定的格式优先。正文局部标题按所属章节相对层级排版，不能与确认目录争用编号，且须满足模板扩展权限。业务表格明确指定列名时验证表形状；普通生成表格禁用继承的单元格序号，模板必填表格保留其原有布局和表头格式。

模型建议继续标红；资料事实不因排版获得事实地位。文档标题来自用户要求，目录预览、草稿和演示产物明确标识。字体规则不会证明实际环境已安装相应字体；渲染替换检查须按报告实际能力解释。

## 分页与格式检查

LibreOffice/UNO 在副本上计算书签页码和 PDF，程序回填 DOCX 的页码域缓存，不替换完整原稿。缓存与最终 PDF 在分页收敛后保存。未安装组件时标记 `requires_office`，Word/WPS 可更新域，不声称已完成实际分页。页面图片由 `pdftoppm` 生成。

最终 Jev 页面评分与低分后的自动优化已取消。当前保留段落、表格等属性的受限格式优化、内容保护和实际分页；格式调整不修改正文、来源、标题身份和模型建议红色，也不能覆盖用户模板指定的格式。这些检查不等于视觉审美验收。资料研究和风格分析仍可使用图片输入；独立的 DocPolish 尚未接入生成链路。

模板任务在渲染、格式修改后的检查及最终发布阶段验证冻结原件哈希与模板格式。检查包括固定章节、样式定义、页面与分节设置、页眉页脚、必填表格及其表头布局；破坏模板约束的结果不能直接作为正式产物发布。

`reformat` 使用已保存正文与文档计划，无模板时使用内置版式，有模板时复用冻结模板，不调用模型。仅当保存的有效格式补丁与当前文档签名匹配时重放，失败保留安全版本；重放不等于新的视觉检查。

## 兼容与验证

旧作业和历史目录经显式读取迁移保留正文、证据和稳定章节身份；新的公开请求仍拒绝旧版强制模板／大纲字段。没有模板的历史计划按原路径运行；有模板的新计划保存完整约束与独立原件快照。旧预览可只读打开，预览资源接口不承担模板选择；用户上传并明确指定 DOCX 用途才进入新的模板分支。

回归覆盖目录结构与局部修正、资料解析、共享事实、业务任务、引用溯源、正文和表格完整性、配图、分页、来源颜色、页面补丁及恢复；模板分支另验证角色冻结、样例隔离、固定结构、必填表格和最终格式保护。模拟模型测试验证契约和边界，不替代真实业务质量验收。
