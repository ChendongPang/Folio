# 业务 Agent 文件研究与执行设计

> English version: [English version](agent-research.md)

本文描述共享资料预处理、目录前研究、V2 文件研究、隔离执行、派生证据及恢复机制。目录、正文节点、业务任务、全局事实快照、审阅和 Word 交付继续采用现有架构。

## 整体协作

协调层仍由 LLM 提出 WorkPlan，再由 `BusinessCoordinator` 校验并执行 DAG、并发、取消和交付。Business Agent 自主决定研究路径；调度器不会规定必须先读 Word、再读 Excel。每个正文节点保持唯一负责人，工具只能访问本任务的输入与产物，不能直接改正文、任务状态或共享事实。

风格示例通过独立的 `style_analysis` 任务处理，与本地三轮业务研究及两轮联网补查 分开计数。程序按请求容量分批提供全部可提取文字，保留跨批观察，检查各文字维度是否形成有依据的结论或明确未出现说明；不因模型没有申请补读而提前停止。可直接读取的 DOCX/PDF 排版属性由程序测量，只有真正需要页面图像的信息才可列为视觉缺项；支持图像输入时仍采用有界原页样本。`structure.md` 描述原件结构，`style.md` 描述十个维度、文字覆盖、依据与未确认项，不把两者混合。

风格原件不进入业务 Agent 的事实目录、`Evidence`、共享事实或检索库。研究、业务理解、节点生成与修复仅获得对应阶段的风格摘要；目录参考组织和标题，正文参考语气、详略、图表说明与表达习惯，Word 和审校参考已验证的有效排版参数。所有摘要来自同一冻结 `profile.json`，不是每个 Agent 独立推断一份风格。风格规则不能覆盖模板硬约束或生成不存在的业务事实，数字统计不成为章节或字数配额。

```text
上传校验、共享原生解析缓存及逐文件 structure.json / structure.md
  → 资料快照预处理：manifest + 权威结构 JSON / 派生 Markdown + content
  → 目录前主 LLM 研究：浏览 Manifest → 按需查看结构、读取原文和补读
  → 有原文依据的目录要求、实际读取记录及尚未解决的问题
  → 完整目录规划 → 结构／模板检查 → 来源要求的目录去向审阅及有界修复
  → 研究充分、范围明确且检查通过 → 用户确认目录
  → WorkPlan、任务依赖和固定的全局事实快照
  → Business Agent 自主研究
      共享结构导航 → 按章节、Sheet、页码等范围读取原文
      每轮 research_step → 文件工具 / 原图 / Python / 转换 / 核验 → 观察结果
      本地最多 3 轮，每轮最多 12 个工具步骤，有据可写时提前结束
      understand_work 区分可查证行动与待用户补充项
      有公开信息查证行动 → 联网补查最多 2 轮，每轮重新判断
      不再有可执行查证行动 → 正文准备；缺项保留待确认，允许的设计建议明确标为模型建议
  → understand_work → 按节点写作 → 抽取与来源校验
  → 业务审阅、跨章精查与局部修复
  → Visual Agent、Word、格式保护和最终分页
```

目录前研究与正文研究共用来源索引和文件阅读能力，研究时机提前到目录生成之前；程序不再把每份文件前 8 个标题和前 12,000 个字符作为目录模型的全部材料。主 LLM 根据用户目标选择要读的文件与范围，有调用、工具、时间及上下文边界。报告的 `ready` 表示本次目录研究足够，`partial` 保留未读、预算或范围缺口，`no_sources` 表示没有普通资料；没有资料时仍可按用户要求与可选模板规划，不能宣称研究过不存在的附件。`partial` 或范围尚不明确时允许展示初稿，但阻止确认进入正文。

目录 `finish` 可通过 `local_research_actions` 明确仍可执行的本地查证行动：非空时继续研究，明确为空且实际阅读、引用和资料取舍检查通过时，允许结束本轮并保留需用户补充的范围问题；旧返回缺少该字段时保持原续研逻辑。尚可读取的评分、技术等章节不能因一次 `finish` 被自动视为研究结束。缺少公司信息、报价或人员证明一般属于正文待补项，不阻塞目录结构；真实范围未确定仍保留 `blocking_gaps` 和 `partial`。

来源要求去向审阅读取真实证据与完整目录，逐项判断是否在实际正文节点的标题／写作说明中得到明确承接。不强制一项要求一个章节，也不允许用笼统标题掩盖具体要求遗漏；排除项需给出适用范围理由。要求多时分批核对全部要求，单项原文不截断，超过预算明确保留缺口。程序验证要求、证据、节点 ID 及每项恰好一次；遗漏经有界修复仍不通过时保持初稿。结构合法与实际阅读充分是两项独立条件，不以目录检查代替正文验收。

目录研究报告保存于目录版本的 `research/report.json`，实际工具动作、来源版本、定位和原文证据同时保留；覆盖审阅每批输入、结果、用量、耗时及失败／取消状态另存 `research-review-attempt-*.json`。通过确认后，`Store.create(..., directory_research=...)` 冻结这些记录到作业 `inputs/directory-research/`，正文任务使用对应节点要求和同版原文证据，继续按需深入研究。研究摘要和模板示例均不会自动变成全局事实；共享事实仍走现有正文抽取和核验路径。目录前研究不会用掉某个尚未创建的正文任务额度，两阶段各自保留有界预算和读取记录。

写作发现缺口时使用本业务任务剩余的补查轮次；普通修复、中断恢复和新研究版本都不能重置三轮本地及两轮联网的额度。三轮指三次有界研究，不是三个文件工具调用。工具、模型和时间总额度仍可提前终止研究。现有 `understand_work` 同时返回 `research_actions`：`local_sources` 指明仍有必要读取或核对的本地范围，`public_web` 指明可公开查证的问题。只有相应行动才触发继续检索；公司名称、报价、证书、内部环境和方案决策等缺项保留在 `open_questions`，没有可用依据时不反复读文件或上网寻找。联网不可用时记录状态，待确认信息继续传给正文和补全流程，不因此虚构项目事实。旧版本已提交 `finish` 却因待补项重新进入本地研究的断点，先用已有证据按新版规则评估一次。事实快照仍按研究版本固定，不新增实时广播或事实订阅。研究产物被登记或脚本成功执行，都不自动赋予其共享事实资格。

新 GUI 作业和 LLM CLI 生成启用 `JobInput.research`；历史未配置研究能力的作业和离线演示保留原研究路径。`research_step` 和 `verify_derivation` 使用主模型，通过现有 `Engine.call` 获得缓存、模型预算、容量检查及审计。Jev／luna 保留原意图、资料选择等有限判断职责；意图为 `chat/analyze/analyze_style/generate/resume_generation/requirements/clarify` 七类，不让判断模型生成 Python。

## 工具协议

所有由模型发起的工具动作通过 Chat Completions 原生 `tools` / `tool_calls` 协议交互。请求声明本阶段允许的函数，使用 `tool_choice="required"`。目录与业务研究启用 `parallel_tool_calls=true`，一次回复支持最多16个调用；其他单一决策任务仍要求一个调用。流式响应按调用索引分别拼接，允许片段交错到达，收完后检查索引连续、ID 非空且唯一、函数名和参数有效，再开始执行。响应必须以 `finish_reason="tool_calls"` 完成；普通回复文本不会被当成命令，不再接受自定义动作 JSON 或“只取第一个 JSON”的容错。

同批互不依赖的文件浏览、搜索和读取最多4个并发执行；依赖前一个结果的操作要等下一次模型请求。脚本、依赖安装、OCR 登记和产物修改等涉及共享状态的动作按原顺序执行，前后两组只读操作也以这些动作分隔，避免共用临时文件、证据或登记状态发生冲突。结果呈现、来源短编号和研究记录按调用顺序提交，不按完成快慢重新编号。`finish` 必须单独提交；与其他调用混在同一批时整批返回对应 ID 的错误，不执行其中的工具，要求模型重新决定。

同次模型回复保存为一条包含完整列表的 `assistant.tool_calls`，各执行结果通过 `role="tool"` 和匹配的 `tool_call_id` 返回。一个工具失败不会丢失其他工具的结果，每个已接收调用都有对应结果或明确错误。正文和结构仍用原文文本／Markdown 提供，只发送一次；容量不足而将部分结果移出上下文时，保留批次调用和对应 ID 的归档说明，不留下没有回传结果的调用，也不把占位说明算作已提供原文。最新结果过长时明确分页。错误和未通过验证的 `finish` 也返回对应工具结果。业务研究在执行前持久保存整批待执行操作，并逐个登记执行身份和额度，重启复用已完成的结果。旧版本已执行历史可作为存档资料参考，不补造原生调用 ID；新请求使用新协议缓存身份，已持久化的待执行操作仍保持原额度和执行身份，避免重启重复执行。

原生函数名使用 `fs_list`、`fs_inspect`、`fs_read` 等；后台工具账本保留 `fs.read` 等既有标识。`ResearchStep` 仅是内部执行记录，保留实际原生调用用于审计及恢复，不是要求模型在文本里生成的协议。函数参数直接包含实际读取／执行参数与公开的 `summary`，可附 `research_notes` 笔记增量；业务研究可附尚缺资料。笔记正文、笔记条数和证据引用数不另设小型固定配额，服从实际请求容量；缺少 `topic` 时仅从该条已有正文首行生成导航标题，不添加事实。历史 `notes` 只作兼容补充，不能用缺省空值覆盖已有笔记。目录 `finish` 的要求通过 `evidence_ids` 引用 `E1` 等原文证据，`selected_ranges` 由程序从证据和实际阅读记录推导，模型不再填写。后台仍逐项验证引用、范围、资料取舍及未解析内容，不能用函数调用绕过业务检查。模型只返回普通文字时，在原有重试额度内带上这段回复，明确告知未执行工具、未保存结论，并要求调用当前可用函数；文字本身不会转成动作执行。

迁移覆盖目录研究、业务文件/Python/产物操作、旧流程下一步动作、资料检索、联网搜索和覆盖审查补读。意图分类、相关性评分、目录正文和风格分析仍是内容／判断结果，保留原有结果校验。工具定义不重复放进系统提示词，独立计入完整请求预算；函数参数使用普通参数 Schema（`strict=false`）并在本地严格验证，不额外叠加 `response_format`。接口不返回原生调用时明确报错，不偷偷回退成文本动作。协议说明见 [OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)。

| 工具 | 实际能力 |
| --- | --- |
| `fs.list` | 模型侧列出文件短编号、名称与类型；完整路径、版本和状态仍保存在后台；也可查看已有产物目录 |
| `fs.inspect` | 直接提供持久化结构 Markdown：真实标题树、Sheet／表头候选／范围、PDF 书签／页码、幻灯片标题；通过短节点编号选择正文 |
| `fs.search` | 可分页的本地词法检索或既有知识库检索；联网阶段由协调器在本地研究结束后推进 |
| `fs.read` | 按 `node_id`、定位、Sheet／单元格、页码读取原文和执行产物；`scope=history/evidence/context` 可分页查询完整工具历史、全部证据及固定上下文 |
| `fs.view` | 查看 PDF／图片的原始页或归一化局部区域；Office 必须绑定受控转换执行记录；使用已启用图片输入的研究模型 |
| `sandbox.exec` | 隔离 Python、固定 Office／OCR 转换、申请白名单依赖 |
| `artifact.save` | 登记和核验派生结果、复用有效产物、建立覆盖清单；`extraction.verify` 请求独立视觉核验，每批 1～2 页 |
| `research.save` | 仅保存当前已读原文的研究笔记；原生函数名 `research_save`，归纳期间不读取新资料 |
| `finish` | 结束本轮研究，保留全部未解问题；不表示全文已获批准 |

文件路径必须属于当前资料快照，拒绝绝对路径、父目录穿越和符号链接。分页结果提供 `total/offset/next_offset/complete/truncated`；读取完整分页范围和原文件已完全可读是不同状态，后者另以 `source_complete` 表示。搜索只证明命中了相关内容，不能证明已经覆盖全部条款。

## 共享研究记忆

目录研究和业务研究复用 `ResearchMemory`，每个目录版本或业务任务保持自己的记录；同一业务任务的兼容补研究会话继承已有成果，不新增跨任务实时事实同步。原文可以退出本次模型上下文，但对应阅读成果与出处必须保留。记忆分为三层：

| 层次 | 保存内容 | 写入责任 |
| --- | --- | --- |
| 阅读与交付记录 | 来源版本、文件与页段、请求编号、实际提供的字符范围、证据编号及完整性 | 程序根据真实工具结果和模型请求记录 |
| 研究笔记 | 相关发现、对目录或任务的影响、推断、无关说明和未解问题 | 模型提交增量，程序校验后保存 |
| 原文证据 | 规范化原文、原始定位、完整工具输出及来源版本 | 程序完整保留，按引用或范围回读 |

下一次原生工具调用可携带上一批资料的 `research_notes`，先保存笔记再执行下一步，正常研究无需每读一批额外调用一个摘要模型。容量压力需要先归纳时，`memory_checkpoint_required` 将本次允许的工具收窄为 `research_save`，由同一个研究模型保存笔记后继续；这类归纳请求仍计入原调用额度。单条包括 `topic`、`text`、`kind`、`evidence_ids`、`unresolved`；修订已有条目时提供 `note_id`。模型不再填写 `request_ids`。`kind` 区分 `source_statement`（资料中的陈述）、`inference`（模型推断）和 `no_relevance`（所引原文与当前任务无关），需要移出无关原文时可登记后者，不能为满足归纳要求编造结论。

程序只接受本研究版本实际交付的证据引用，不以后台提取成功代替发送；批次关联由程序根据 `evidence_ids` 与交付账本恢复。归纳状态只覆盖所引用的证据，不把同批其他未引用原文一并标记完成，也不证明归纳语义完整。状态“已归纳”不表示来源覆盖或内容验收通过，未交付的尾部仍保持待处理。笔记按条追加，显式修订保留原条目历史；重复提交按调用与内容身份幂等处理。省略 `research_notes`、空列表或缺省 `notes` 均不清空旧记录；修订条目未提供 `unresolved` 时也保留旧问题，明确给出空列表才清除该条问题。笔记、交付记录和待归纳状态随目录报告或业务检查点保存，`research.md` 从同一份记录生成供人阅读，不维护第二份可独立修改的权威状态。历史笔记与账本中的请求编号仍保留用于追溯，不再要求模型维护这些内部编号。

正常上下文保留用户要求、模板约束、相关固定事实、本次研究全部工具往返、读取进度、全量笔记和未解问题。清单和结构已经发送过、原文已经归纳或笔记超过固定长度，都不是提前缩减历史的理由。先检查包含工具定义在内的完整请求，超过当前模型输入容量后才缩减视图，优先移出已有带出处归纳的旧原文；缺少归纳时由同一个研究模型先整理当前已提供资料。归纳请求可专注其中一批，其他批次仍保存为待处理，不因这次未展示就标记完成。确实超限才提供笔记主题索引，完整条目通过 `fs_read(scope='context', field='research_notes')` 分页取回，完整历史索引使用 `field='research_history'`。后台完整原始记录始终保留，不能将未展示误报为已删除或已解决。研究笔记既不能替代正文引用核验，也不能证明未提及的条款不存在。

正文发现新的 `writing_gaps`，或用户明确继续后创建新研究会话时，若仍是同一业务任务，且任务职责、章节、依赖、指令、工具策略、资料和全局事实快照一致，新会话继承旧笔记、原生工具历史、证据、交付记录和阅读进度。首次补研究请求就带上这些记忆及新增缺口。兼容性校验失败则保留旧存档，不把旧结论带入新的研究范围。旧版本会话可根据已有 assignment 和会话身份校验后继承。

兼容补研究沿用原任务工作目录，保持证据编号、分页游标、OCR 和产物核验记录有效；各会话的任务输入另存于 `context/sessions/<round_id>/assignment.json`。只继承知识和历史，不继承完成状态、停止状态、连续无进展计数或 `pending_*` 操作。恢复一个已存在的会话始终优先于继承，未完成工具批次仍按原有恢复规则处理。工具和模型额度继续由账本管理，继承旧结果不重新计费，也不自动授予新额度。新授权会话只获得已继承历史记录 ID 的回读权限，不开放其他业务任务或整个旧授权范围。

历史入口包含文件名、真实页码或定位、证据编号和归纳状态，避免只给裸 `request_id`。复读已读范围时应通过 `review_reason` 说明具体核实问题；程序允许合理复核，持续无新增证据、有效笔记或缺口进展时按原有规则结束本轮并保留缺口。分页续读属于新增范围，不因文件相同被视为复读；合理复核也不能取消原有调用和时间上限。

研究完成的条件是当前任务所需依据和缺口足够清楚，不要求所有附件全文同时出现在最后一次请求。待归纳状态控制原文能否压缩，不因读过但未采用的证据尚无笔记单独阻塞目录 `finish`。目录仍须提交带真实、同版、已交付原文依据的要求，并保留未读内容和真实需求覆盖检查。笔记中的推断、风格示例的业务内容、未核验 OCR 或计算结果不会因此进入全局事实；已确认事实继续使用现有抽取、审阅和固定快照机制。

## 共享资料预处理与读取

`research/source_index.py` 的 `prepare_uploaded_source` 在上传校验时复用 `cached_source` 的解析对象，在上传原件旁生成 `structure.json` 和供人及模型阅读的 `structure.md`。`SourceIndex` 在资料快照进入规划或研究前生成统一清单及绑定该快照版本的结构、正文副本；底层读取由 `research/formats.py` 完成。这些都是本地确定性处理，不调用模型，不生成业务结论。普通聊天、目录规划、LocalKnowledge 和 Workspace 复用同一版本，不再分别打开 Office／PDF 重新解析。聊天按结构和正文预算提供摘录，不再把 PDF、Excel、图片作为 UTF-8 文本读入。各入口共用数据目录下的 `source-cache/`，缓存键包含完整文件 SHA-256、格式和读取器版本；同内容文件改名或复制到新快照仍可复用。内容或读取器版本改变时重新解析；缓存损坏时重建，仅在没有有效解析对象可复用时重新解析原件。

每份资料快照旁的 `sources.index/` 包含 `manifest.json`、`structures/<file_id>.json`、`structures/<file_id>.md` 与独立 `content/`。JSON 是精确定位、版本、范围和解析状态的权威索引；Markdown 由 JSON 确定性生成，只描述内部结构，不放解析警告、研究建议或业务摘要。旧索引缺少 Markdown 时直接从现有 JSON 补生成，无需重新解析原件。清单记录文件版本、解析状态及缓存哈希；正文保持规范化的原始文本块。缓存写入使用文件锁和原子替换，读取时核对原件版本与缓存完整性。目录修订搬迁时同时保存原件和索引；业务任务共享同版原生结构与正文，自己的研究笔记、证据选择和 OCR 结果仍独立保存。旧的直接 `LocalKnowledge(directory)` 调用保留只读行为；引擎显式传入共享缓存路径。

内部结构节点保留 `node_id`、`parent_id`、标题级别和正文范围；模型使用文件 `F1`、节点 `N005` 等短编号，`N000` 表示全文。映射绑定当前快照，真实文件路径、长节点 ID 与哈希不必重复进入每轮请求。读取父章包括其子章，范围在下一个同级或更高层标题处结束。`fs.inspect` 不打开整份正文缓存，也不生成 Evidence；正常大小的结构一次完整返回，不再默认截成 50 个节点。只有完整文本超过本次预算或明确请求 `limit` 时才按完整节点分页，预算包含标题和继续入口；单个节点无法容纳则明确报错，不返回永远无法前进的空页。无书签 PDF 的连续页可合并为页码区间，后台仍保留每页独立定位。

结构浏览是推荐的渐进研究方式，不强制每次正文读取前都执行 `fs.inspect`。文件、节点和页码用于定位，`E1` 等证据编号用于笔记和结论引用；内部读取范围与请求编号由程序管理。已明确定位并读取的正文不会仅因缺少结构浏览记录而阻塞目录结束，真实来源版本及实际交付仍核验。目录可以引用已交付页段，不强制读完其所在的整个查询范围；范围完整性及未读状态保持真实，不将局部引用算作整章覆盖。

`fs_read(file=..., node=...)` 默认完整返回所选章节及子章节。模型可以同时调用多次 `fs_read` 选择多个章节，程序并行取出正文，再按这些结果与既有上下文组成的实际请求检查共同容量。取消固定 2,000 字符切片、默认 20 条以及 100 条上限；只有所选内容超出剩余请求容量时才分页，不为每个工具重复分配整个输入窗口。来源块仍保留原始定位，分页状态为块序号 `offset` 与块内 `character_offset`，由持久化游标封装；`read_segments` 记录实际返回的字符区间。单个段落只返回一部分时，未读尾部不会被算作完整覆盖，恢复后可准确续读。工具输出同时说明剩余范围；显式旧分页参数仍可使用。

任务内 `.workspace/navigation-references.json` 持久保存节点短编号：初始按原生索引编号，新增 OCR 页只追加编号。后补的第 1 页即使排在已识别的第 2 页之前，也不会改变后者已有编号；移除节点的编号不分配给其他节点，重启仍恢复原映射。源索引的静态 Markdown 不受任务 OCR 影响。

`fs.read` 返回原文、短来源编号和继续入口，保留标题、表格行等必要结构，不让另一个模型改写或摘要正文。后台根据原文件版本、原始定位和字符片段生成 Evidence ID，再将模型侧短引用还原为原身份核验。读取相关内容时附带实际解析状态，结构 Markdown 本身不混入这些警告。新增结构导航不会改写原文或来源身份，模型不能自报来源身份。

程序提取结果与模型实际收到结果分别记账。目录研究只把确实随请求发送的原文计入已提供范围，`finish` 可以引用已交付的证据，但不能宣称尚未提供的分页已经读完。业务研究另保存 `model_deliveries`，记录每次请求提供的观察、文本摘要哈希、字符数及是否完整；工具账本仍保存完整执行结果。最新工具结果不能因包装膨胀被整条静默丢弃，过长时明确分段并提供历史继续入口。这里的“已提供”是可审计的传输事实，不声称能证明模型理解了全部内容。

| 格式 | 原生读取 | 明确边界 |
| --- | --- | --- |
| DOCX | 正文顺序、真实标题层级、表格行、修订读取视图和批注元数据 | 图片／文本框标记未读，需隔离转换与 OCR |
| MD／TXT | UTF-8 文本、原始行号；Markdown 的 ATX／Setext 标题层级 | 不把代码块内容当标题；非 UTF-8 文件明确拒绝 |
| XLSX | Sheet、首个非空行的表头、单元格与有限合并信息、隐藏／空 Sheet、公式及缓存值 | 表头选择明确标记规则，不代表业务字段已经理解；读取不计算公式，缓存值未经核验 |
| PDF | 原生文字、真实书签层级、页码、块定位 | 无书签时仅按实际页码导航，不推测章节；书签章节按页读取，边界页可能包含相邻章节；无文字页标记 `needs_ocr`，加密 PDF 明确拒绝 |
| PPTX | 幻灯片文字、表格和备注 | 图片、图表等未读视觉内容要求转换处理 |
| PNG／JPEG／TIFF／WebP | 尺寸、页数、格式有效性 | 图片文字可经隔离 OCR 或独立核验的视觉提取读取，不能从文件名猜测 |

上传、原件解析和风格原件读取不再设置文件字节大小上限，Office 解压后总字节上限也已取消。GUI 每会话仍最多 200 份；读取器保留 Office 5000 条目、单文件文本 800 万字符、10 万文本块、PDF／PPTX 2000 页、Excel 展开范围 50 万单元格等独立内容范围限制。超过这些范围明确要求拆分，不把截断结果冒充完整资料。取消原件体积限制不改变模型上下文额度、图像输入和工具分页规则。目录前研究从同版 Manifest 获取资料导航，再由工具分页查看完整结构与实际原文；短 catalog 和聊天摘录只用于导航，不能替代目录前研究。无书签 PDF 保留无目录提示，不能用页码名称冒充章节；完整页导航由研究工具提供。

原生文件无法解析时，索引保留 `unreadable` 和原因；格式合法但存在扫描页、图片等未读范围时保留结构与缺口，不把缓存完成解释为 Agent 已通读。每次读回核对原件版本，资料发生变化时要求建立新的研究版本。Excel 范围读取生成原始行的准确字符片段，仍可回溯原始单元格行。本地词法检索继续使用相同 Evidence 块；这里的结构索引不是 Wiki 或向量 RAG。

PDF 同页有原生文字和图片／矢量绘图时仍记录未读视觉范围，标题或页码不能证明整页完整；Excel 绘图按所属 Sheet 保留未读状态。仅有明确装饰标记的对象可直接排除，不按图片大小猜测业务重要性。完整性按本次选定的页、章节或 Sheet 判断，不让范围外的未读页阻塞已完整范围。

文件 SHA-256 在进程内按设备、inode、大小、mtime_ns、ctime_ns 有界复用，改变文件后即使恢复 mtime 也会重新校验；进程重启后的首次访问仍需计算哈希。词法索引使用有界缓存，各任务 Evidence 独立复制。资料准备在线程中执行并纳入作业总超时；取消在文件、分块和锁等待之间生效，当前解析／原子写入结束后才释放作业锁。

## 任务目录和容器

```text
<数据目录>/
├── source-cache/                    按内容、格式、读取器版本复用的解析对象
├── directory-drafts/<revision>/
│   ├── sources/                     目录版本对应原件
│   ├── sources.index/               随目录版本保存的资料索引
│   ├── research/report.json         目录前研究、原文证据和范围缺口
│   ├── research/research.md         从报告同源导出的带出处研究笔记
│   └── research-review-attempt-*.json  来源要求去向审阅的逐批输入输出
└── jobs/<job>/research/
    ├── sources/                     研究原件快照
    ├── sources.index/
    │   ├── manifest.json            文件版本、状态与缓存引用
    │   ├── structures/              精确 JSON 索引及同名 Markdown 导航
    │   └── content/                 同版规范化正文
    ├── ledger.sqlite                工具调用与额度账本
    └── tasks/<task>/<initial_round>/ 兼容补研究会话共享该工作目录
        ├── research.md              从当前持久研究记忆导出的可读笔记
        ├── context/                 当前 assignment、事实快照，只读挂载
        │   └── sessions/<round>/assignment.json  每个会话的任务输入
        ├── scripts/                 工作区脚本入口
        ├── scratch/                 当前任务临时文件
        ├── artifacts/<execution>/   每次执行独立产物
        ├── .workspace/              本任务的 OCR／转换读取缓存
        └── .research/               宿主管理的脚本、执行与产物记录
```

任务内 OCR 的正文与结构按同一代保存，最后原子更新提交指针；中断前未提交的新文件不会被恢复为成功结果。旧 `v2.1/v2.2` OCR 缓存核对原件哈希和提取身份后，迁移为当前原生正文加原有 OCR 块，保留已引用的 OCR 证据身份；原件共享缓存不会被迁移或 OCR 改写。

目录持久保存，容器按执行分配。源目录、上下文和历史已提交产物只读挂载；当前执行只能写自己的临时目录和产物目录。模型代码不在宿主 Python 中执行，不能访问 Docker socket、宿主密钥或其他任务目录。缺少 Docker／镜像时返回明确工具错误，不回退到宿主执行。

容器使用禁网、只读根文件系统、非 root 用户、删除 capabilities、禁止提权，并限制 CPU、内存、进程数、文件大小、输出和执行时间。取消与恢复会清理对应容器；完成后重新核对输入及输出哈希，产物异常不能登记为完成。输出文件不通过文件名存在就取得可信状态。

构建四种环境：

```bash
docker build --target base -t folio-research-base:v2 -f docker/research/Dockerfile .
docker build --target data -t folio-research-data:v2 -f docker/research/Dockerfile .
docker build --target office -t folio-research-office:v2 -f docker/research/Dockerfile .
docker build --target ocr -t folio-research-ocr:v2 -f docker/research/Dockerfile .
```

`base` 提供基础文件与表格库，`data` 加入 pandas／NumPy／SciPy，`office` 提供 LibreOffice 和 PDF 工具，`ocr` 加入中英文 Tesseract。每次执行记录最终镜像的不可变摘要；修改同名镜像后，不复用依赖旧摘要的结果。

运维策略来自数据目录 `settings/research.json`，也可由 `FOLIO_RESEARCH_CONFIG` 指定。常用项包括 `profile_images`、`max_concurrent`、`cpu_limit`、`memory_mb`、`pids_limit`、`max_output_bytes` 和依赖策略。这些配置不由用户资料或模型动作修改。

动态依赖必须匹配运维白名单中的包名、固定版本及 wheel SHA-256，且依赖闭包明确。仅固定安装器可使用受控网络，模型 Python 始终禁网；安装时不挂载资料。依赖缓存绑定镜像摘要与完整锁定集，拒绝任意 URL、可变版本或未批准依赖。镜像构建和批准依赖下载可能访问网络，但不会调用付费模型。

## 来源、计算和 OCR 核验

普通原文证据包含源文件、版本、定位与文本。计算产物登记时还必须绑定真实执行记录、输入证据、脚本哈希、镜像及依赖摘要、输出文件哈希、计算方法与业务主张。产物记录有后台签名；模型无法通过自行填写 `passed=true` 改变核验状态。

`verify_derivation` 独立读取原始范围、实际脚本和结果，分别检查来源、计算及业务口径。模型必须同时确认三项，后台再记录验证；资料不全、原文超过核验容量或口径不明确时保持未核实。正文引用合法仅证明来源存在，后续抽取、局部校验及全局审阅继续执行。

例如“共有 58 个必填字段”，除了执行成功，还要检查是否把行数误当字段数、是否去重、Sheet 是否选对、空值及公式缓存如何处理。

固定转换包括 `office_pdf`、`office_recalculate`、`ocr` 和 `office_ocr`。后者在同一个受信脚本中完成 Office→PDF→OCR，页数取实际转换结果，仍绑定原 Office 文件哈希。OCR 原文登记为 `extracted:` 证据，保留执行编号、镜像摘要和页码，并设置 `requires_extraction_review`。本版不会仅凭 OCR 正常返回就把关键文字视为已确认；未独立核实的 OCR 证据会阻止共享事实与发布，可保留在待确认草稿中，用户明确补答继续走既有确认流程。

OCR 可以指定最多 20 个原始页码，例如 300 页资料只处理 `[180]`；未指定时整份处理仍限制 100 页。Office OCR 保存实际转换 PDF 供查看和核验，原页图像绑定原文件、转换脚本和执行产物哈希。`verify_extraction` 独立对照每页完整原生／OCR 文字及原图，检查数值、否定词、表格关系和流程箭头；通过后由代码签署不可变回执，绑定原文件版本、提取块、页码、原图哈希和审阅请求身份。通过范围的 OCR 可参与覆盖和后续事实校验；来源或提取内容改变会失效。空白／装饰页也必须明确核验。查看原图不等于批准，业务 Agent 不能自报通过。Office 原生章节与渲染页缺乏可靠映射时，不推测对应关系；整份 Office 的视觉缺口仅在全部渲染页核验后解除。

对于流程箭头、分支返回位置、原型控件关系等 OCR 不能完整表达的信息，业务 Agent 可在看原图后请求 `artifact.save(operation="visual.extract", path, page, text)`。独立 `verify_visual_extraction` 对照完整原页逐句核验该描述，通过才生成带签名的 `visual:` 证据；“描述可信”与“覆盖整页”分别判断，部分可信描述不能解除整页未读状态。完整视觉释义可作为该页的覆盖条目，错误或模糊描述不登记为证据。跨任务可引用已核验的视觉证据，但不能用另一任务的回执默默关闭自己的范围覆盖。

OCR 补充只更新当前任务的读取覆盖层，不回写公共 `SourceIndex`。PDF 可以继续按真实页码和书签范围读取提取文字；Office 转换页单独作为页节点导航，无法可靠对应原 Word 章节、Sheet 或幻灯片时，不强行把 OCR 文字归入这些原生节点。任务之间不会因共享解析缓存而混用未核实的识别结果。

对于全部字段／条款覆盖要求，研究开始时独立检查正式要求、实际章节职责和资料目录，形成覆盖范围契约；后端强制建立所需清单，无法定位或读取的范围保留为待确认，研究 Agent 不能通过省略建清单操作绕过。没有全量要求的章节不新增这种义务。CoverageManager 从完整解析范围枚举条目，最终按实际正文引用逐项复查；长原文的多个真实字符片段须合并覆盖整个条目，少一段仍不算完成。“不适用”声明经过独立审查才可排除。未读取的扫描页、视觉范围、截断内容和未处理条目不能被搜索结果或模型摘要抵消。

范围审查默认取得完整文件清单与结构，只有实际容量不足才分页，并保留后续导航。结构请求可按标题、`node_id` 或 `locator_prefix` 定位，兼容明确等价的 `structure_node` / `structure_id` 别名；缺少文件编号时，仅在单文件或定位唯一时补足，歧义和越界仍报错。每个职责分区最多三次审阅，大任务最多分为八个保留完整正式要求的职责分区。已独立确认的覆盖义务不会被后续导航响应遗漏或审阅失败清除。同一正式职责和资料快照下复用范围契约，跨研究轮次同时继承覆盖记录；普通修复文字、写作缺项或新增阅读证据不触发整份范围重审。正式职责、来源快照或新增明确范围改变时再审查。范围确认后重新枚举所选原文及已独立核验的 OCR／视觉内容。同一正式范围的自动清单更新时，旧自动清单退出当前检查但保留签名历史；手动登记范围始终保留。不能用联网资料或模型建议伪造原文件的完整覆盖。

派生核验失败或超过核验容量时，问题单独持久保存，不能被研究结束时的空缺口列表清除。后续同一产物通过核验，或独立审阅确认实际正文未使用该主张、任务职责已经被其他原始依据满足，才可以解除；正文或来源版本改变后重新检查。

## 预算、恢复与验收

本地最多三轮，默认每轮 12 个工具步骤（`max_steps_per_round`）；每业务任务还受 50 次工具操作、60 个研究步骤、40 次研究模型调用的总额度约束，脚本累计 600 秒、单次最多 120 秒，并为后续正文和审阅保留模型额度。研究模型请求和失败重试在 Store 同一事务内同时登记研究额度和整篇总账，缓存命中不扣费。随后最多两轮联网补查，各次联网在请求前持久登记，查询与证据理解继续受整篇模型总账约束。工具次数、研究轮次与时间由持久账本独立计数；普通重试或修复不清空累计额度，用户显式补答续跑提供新的有界本地研究额度，并进入新的研究版本身份；既有联网尝试保留累计计数。

一条模型回复包含多个工具时，模型调用计一次，工具操作和轮内步骤逐个计数；并发不会增加可用总额度。取消时等待在途工具退出并保留已登记结果，然后才释放工作目录或恢复下一轮。

所有研究和业务动作默认使用 128,000 Token 输出额度，不再为证据理解等步骤单独压低输出。单次文件工具结果默认允许 600,000 字符并保持渐进分页；目录研究累计原文字数 `max_evidence_chars`、风格分析累计原文字数 `max_total_chars` 默认均不设硬限，只有显式配置数值时生效。每次请求仍受完整上下文 600,000 Token 预算和服务实际窗口约束，调用次数、轮次与时间额度继续独立执行。

本次研究默认携带完整工具历史和全量笔记，后台始终保存完整原始历史，证据、笔记和历史仍可按文件、定位或 request_id 分页读取。研究请求复用实际容量检查，统计原生工具定义、消息、笔记和输出预留。Runtime 默认输入预算为 600,000 Token，旧配置缺失或 null 同样生效；切换模型不退回旧字符限制。已知更小的 `context_window` 时，输入、输出和余量仍按该窗口校验。服务不能计数时，显式编码使用 `local_tokenizer_estimate`，否则默认 `o200k_base` 并标记 `default_tokenizer_estimate`；估算不等同供应商准确计量。完整请求超限时先确保退出窗口的旧原文已归纳，再按需要将笔记、事实、职责、依赖等工作视图替换为可分页导航，不改写固定快照或删除持久笔记。最小导航仍超限时明确记录容量限制，进入后续缺口处理，不能悄悄丢弃职责或冲突。具体参数和部署说明见[请求上下文与容量设计](context-and-capacity.zh-CN.md)。

工具先登记请求再执行，结果完成保存后提交。中断请求不会被当作成功，也不会静默重跑存在副作用的旧请求；Agent 可根据失败记录调整后提出新操作。已经完成且身份匹配的结果可恢复使用。跨任务复用仅接受通过核验且来源、环境与产物仍匹配的记录。

用户显式继续暂停或失败的作业时，为已失败的请求开放一次有界重试窗口，涵盖暂停前已经失败的并行子任务。成功缓存、正文、研究断点、总调用数和分阶段额度均保留；重复点击继续或未发生新失败的暂停切换不叠加额度。服务启动不会自动恢复用户主动暂停的任务。

修复提示改变只产生新的研究问题；正式任务、资料、事实和依赖版本不变时，仍继承已有笔记、阅读记录和覆盖范围。旧版含修复提示的记忆键通过原始任务记录核对后迁移，不直接放宽版本检查。新版覆盖审查也允许旧版失败契约重新检查一次，保留已确认范围及实际消耗；成功契约直接沿用，新版失败不能靠重启反复重置。

事实抽取请求保留完整正文，并在 `fact_extraction_scope` 中明确列出可抽取事实的段落和仅用于摘要的模型建议段落。混合引用模型建议和真实依据的主张仍拒绝进入事实库，纠错信息说明应保留事实部分、将方案建议留在摘要中；不通过删除无效引用来伪装事实有依据。

验证分为格式与权限边界测试、真实本地容器／Office／OCR 执行、模拟模型的完整流程回归，以及另行授权的真实模型文档验收。前三类通过不代表模型能稳定分析任意复杂材料，也不代表 OCR 或复杂 Excel 公式天然正确。测试方法与验收边界见[测试指南](testing.zh-CN.md)。

## 覆盖检查报告与错误说明

覆盖核验的完整结果保存在任务目录 `.research/coverage_reports/<coverage_id>.json`，包括全部缺项、定位、原因和本次检查的章节版本。`Finding.description` 最多 3,500 字符，覆盖问题仅写缺项数量、清单编号和简短说明，不嵌入缺项 JSON。只读发布核验不覆盖已保存报告；缺项仍进入待确认处理，不因缩短说明而视为检查通过。本地数据校验异常显示为内部校验失败，只有可追溯到模型调用的输出校验错误才归类为模型输出错误。
