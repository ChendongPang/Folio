# 前端 GUI 设计

> English version: [English version](web-workspace.md)

## 当前交互

Folio 是面向多份资料的文档工作台。用户先收集资料，在对话中说明需要什么文档，系统直接规划完整目录，用户确认后才启动正文生成。

```text
批量上传资料 → 描述文档要求 → 完整目录 → 确认 → 生成与下载
                                 ↑        │
                                 └─ 修改建议 / 重新规划
```

GUI 不提供旧版模板推荐、模板库选择、大纲用途分配或封面确认流程。用户可以直接上传一份 DOCX，在资料库将其用途设为“文档模板”；也可将已上传文件设为“风格示例”，仅借鉴写法与排版。有模板时保留指定结构与格式；无模板时按需求和业务资料自主规划，采用经确认的风格参数，其余使用内置版式。界面已移除“文档类型／通用文档”选择器，用户在对话中说明所需类型；创建会话不传 `guide_id`，沿用后台通用文档默认值。后端 API 和 CLI 仍支持可选 URD/SRS 写作指南，旧会话冻结的指南不因界面变更而清除。模板准备方法与当前支持范围见[用户模板设计](templates.zh-CN.md)。

## 实现与视觉

前端使用 Vue 3、TypeScript、Vite，源码在 `frontend/src/`，FastAPI 提供 API 和构建产物。界面使用白色画布、黑白层次、细线边界和等宽标注，绿色与红色用于成功、失败等状态。左侧是会话历史，中央是资料入口与对话，右侧目录预览可展开或收起；手机目录确认保持在对话中，避免被预览层遮挡。

产品品牌为“Folio”，侧栏采用首字母大写的 `Folio` 字标，书脊与折页构成的几何图形统一用于导航、助手头像和浏览器图标。图标使用原生 SVG，在小尺寸下保持清晰；页面标题、助手署名与自称使用同一名称。内部统一使用 `folio`：Python 包与 CLI 为 `folio`，默认数据目录为 `.folio`、数据库为 `folio.sqlite3`，浏览器存储键使用 `folio.` 前缀，环境变量使用 `FOLIO_` 前缀。已有工作空间须按[迁移说明](workspace-migration.zh-CN.md)处理目录和活跃路径，不能仅凭品牌一致认定历史数据已完成迁移。

输入区只保留正文输入、添加资料与圆形发送按钮，取消顶部装饰文字和独立“生成目录”按钮。发送文档要求后由已有意图识别进入目录规划，目录确认仍单独操作。任务进行中同一位置显示圆形控制按钮：文档生成使用暂停图标，暂停后使用继续图标，普通回答使用停止图标。

桌面端可拖动右侧预览栏的左边界调整宽度，并为中央对话保留可用空间。预览栏内部上下分区：上方为完整目录结构，下方为逐页版式预览，两区分别滚动；中间分隔线可上下拖动。分隔线支持键盘方向键、Home/End 和拖动时 Escape 取消。宽度和上下比例作为本机界面偏好保存，刷新后恢复；窄屏预览使用受视口限制的浮层，不显示左右拖动手柄。

- `App.vue`：主画布、上传入口、输入区、导航与流程状态。
- `useWorkspace.ts`：会话、资料上传队列、草稿、目录版本与 SSE 生命周期。
- `MaterialsPanel.vue`：资料库、业务资料／文档模板／风格示例用途选择、搜索、筛选、分页、移除和失败重试。
- `WorkflowActions.vue`：完整目录、确认、修改建议、重新生成与风格说明查看入口。
- `DocumentPreview.vue`：目录树、真实 Word 结构／页面预览和目录下载。
- `MessageList.vue`：消息、处理进度、错误、审阅与最终 Word 下载。
- `ConfirmationPanel.vue`：待确认问题答复、本轮调用额度、重新检查与旧草稿入口。
- `ModelSettings.vue`：模型配置、连接测试和可选服务。

```bash
npm --prefix frontend ci
npm --prefix frontend run build
uv run folio serve --port 8765
```

日常开发使用 `npm --prefix frontend run dev`，API 默认代理到本机 `8000` 端口。构建包括类型检查，产物写入 `src/folio/web/dist/`。HTML 不缓存，资源文件名包含内容哈希；缺少构建产物时首页给出构建说明，API 仍可访问。

## 上传资料与文件研究

上传文件默认是业务资料 `source`，支持 DOCX、MD、TXT、XLSX、PDF、PPTX、PNG、JPEG、TIFF 和 WebP。所有已保存文件均可选择“业务资料／风格示例”，DOCX 还可选择“文档模板”；模板为 `template`，每个会话最多一份，风格示例为 `style_reference`。多份风格示例以附件列表中的第一份为主参考，其他示例单独记录，不自动混合冲突风格。文件名不决定用途。每个会话总计最多 200 份，不设置单文件上传体积上限；前后端仍拒绝空文件和不支持的文件格式。前端最多同时上传 3 份，其余排队。后端流式接收并写入原件，等待解析和结构预处理结束后返回成功。资料库按文件名搜索、按状态筛选，每页最多显示 50 份。

“排队中”“上传中”“上传失败”“已保存”仅表示文件传输与持久化状态。失败可重试或移除。成功上传立即绑定原会话，草稿保存不覆盖资料列表。切换会话取消未完成队列，已保存文件由服务端恢复，旧请求不能写入新会话。

用途通过独立 PATCH 请求保存，不借文字草稿覆盖文件绑定。请求完成前保留已保存的用途并显示“保存中”，阻止发送、删除及其他用途修改；失败时保留原选择并展示原因。第二模板返回明确错误，用户须先移除旧模板，或明确将旧模板设为普通资料；系统不自动降级模板。用途与文件一起保存和恢复，缺少用途的历史文件默认普通资料。

目录生成前先固定原件快照，主 LLM 浏览 Manifest，再按需查看完整内部结构、搜索和分页读取相关原文。目录研究最多三轮，记录真实读取范围并区分影响目录的缺口与正文待补信息；不再直接用文件开头摘录代替研究。模板单独冻结并提取固定章节、填写要求和必填表格，不把示例业务正文作为事实来源。确认后的正文阶段继承对应的同版原文证据，Business Agent 继续自主文件研究，可精确读取、搜索并在隔离容器执行 Python、Office 转换和 OCR；研究资料目录只包含普通资料。图片和扫描页的上传成功不代表 OCR 已完成，未核实提取结果继续保留待确认。工作台没有知识库选择、Wiki/RAG 待接入或知识工程流程；本地搜索直接使用上传资料。部署与来源边界见[文件研究与执行设计](agent-research.zh-CN.md)。

存在风格示例时，先在独立快照上进行程序统计与全文文字分批分析，生成 `style/style.md` 和可执行参数 `style/profile.json`，再规划目录。示例原文只进入专用风格分析请求，不进入普通聊天摘录、目录资料研究或全局事实；内容相同但改名的业务附件也按哈希隔离。界面显示分批读取及完成检查的当前步骤，说明文件记录实际文字覆盖和视觉缺项。风格分析有调用、累计字符和片段上限，触及限制或语义检查未通过时保留未完成状态，不把文字读取完成当作视觉全文审阅。无变化且可复用的分析结果从缓存读取；旧版抽样缓存不能充当新版完整分析。

用户也可直接说“分析这份风格示例”“看看范文排版”或询问其中具体风格，意图 `analyze_style` 独立执行风格分析，不创建目录或正文任务。按当前附件 ID 选择目标，仅接受已标为 `style_reference` 的文件。完成后发送结果卡与可查看的 `style.md`，再依据已提取结果流式回答用户的问题；普通聊天也能读取当前文件版本对应的风格摘要。目录确认阶段保留聊天输入，发送消息不等于确认目录。分析咨询标为 `discussion`，不会改变需求版本或撤销既有目录。

文件增删、用途改变或写作指南改变会使旧目录失效。移除只解除当前会话引用，不删除其他历史任务引用的原件与快照。正在生成或暂停的任务保留原输入，必须结束当前任务后再调整；服务端用同一会话锁保护上传绑定、移除、用途修改和生成确认。

## 目录确认

会话保存 `directory_review`，包含 `revision`、`phase`、用户需求版本、资料引用、理由和 `directory.sections`；生成的目录预览放在 `directory.preview`。存在风格说明时，`directory.style_url` 指向当前目录版本的 Markdown 查看接口，确认区显示“查看风格说明”，在新标签页以纯文本展示。前端保存各条消息的目录快照，只有当前版本的生成和修改按钮可以操作；历史风格说明仍可查看。

`directory.research` 展示实际阅读的文件、章节范围、字符数与待解决问题，目录预览上方可展开“资料研究记录”，也可下载完整 JSON 记录。统计只表示原文曾返回给模型，不表示全文读完或理解率。`directory.confirmable=false` 时显示目录初稿并禁用确认，服务端也拒绝绕过前端直接确认；修改建议与重新生成仍可用。旧版没有目录前研究记录的目录保留查看，但必须重新生成后确认。覆盖审阅检查每项已研究要求是否在目录节点或写作说明中有去向，剩余遗漏显示为待解决问题。

用户需求独立保存在会话的 `requirements` 中，每条原文记录来源、类型及顺序，整个集合带有内容哈希 `revision`。已有意图识别同时区分正式要求、普通咨询和待澄清消息，只把正式要求及明确修改建议加入完整需求，不新增模型请求；明确的后续修订覆盖它所修改的要求，其余原始约束继续有效。目录与正文规划不再只取最近8条消息或最后11,800字符，模型不参与压缩这份记录。

消息的 `requirement` 审计记录包含 `status/kind/source`，意图判断完成时另存 `intent`。`generate/requirements` 分别成为 `active` 的初始要求或修订，普通聊天成为 `discussion`，含糊意图成为 `clarification`；纯界面命令标为 `command`。已有 Jev / luna-decisions 意图路由继续支持这些分类。判断失败保留 `pending`，不把不确定消息直接作为要求或静默丢弃；存在此类消息时禁止生成或确认目录，用户重发相同内容完成判断后，旧记录标为 `resolved` 并保留关联。升级前无分类记录的历史约束保守保留，不自动移除已冻结要求。咨询或待澄清消息本身不改变需求版本。

目录修改建议在会话和需求记录中持久保存。重新规划丢弃旧目录提案，但继承用户全部要求与修订。确认按钮、重新生成按钮的固定文案、问候语不写入需求；修改建议框的原文只记一次。需求累计超过 600,000 字符时返回明确的容量错误，保留原文和旧目录，不截断后继续调用模型；用户需要新建会话并提供整理后的完整要求。完整规划请求还受模型配置的目录容量预算约束。

| 动作 | 结果 |
| --- | --- |
| `chat` | 普通流式对话；识别到明确写作要求时直接规划目录 |
| `generate` | 按当前资料和需求规划完整目录，不生成正文 |
| `revise_directory` | 保存 `advice` 原文并修改当前目录，成功后绑定新的需求与目录版本 |
| `regenerate_directory` | 从完整需求、历次修订与当前资料重新规划，不沿用旧提案 |
| `confirm_directory` | 核对需求、文件及用途仍与目录快照一致，创建正文作业，冻结业务资料、可选模板、风格示例及已采用的风格说明 |

修改、重新规划与确认必须携带当前 `selection_revision`。服务端校验会话归属、目录版本、需求版本、文件 ID、用途、写作指南和任务状态；旧按钮、并发重复确认或失效输入不能启动新任务。新增需求或修改失败后保留上次目录供查看，并保留新的修改要求；旧目录不能代替新要求的确认，需要成功修改或重新规划后再确认。

目录元数据与 `JobInput.requirements` 使用同一份需求快照，`JobInput.user_request` 与其完整文本一致，作业输入目录另存 `requirements.json` 供追溯。升级前生成且没有需求快照的旧目录返回 HTTP 409，提示重新生成；已创建作业仍可读取原有输入与检查点。局部目录修订使用稳定节点 ID，并携带完整需求上下文；没有原大纲或大纲引用协议。

目录元数据另存 `source_roles: [{id, role}]`，缺少该字段的历史目录只允许全部普通资料。选择模板后另存 `template.docx` 和 `template-contract.json`；程序将可信约束绑定为计划中的 `template_section_id`、`required_tables` 和 `allow_subheadings`，不要求前端或模型自行编造绑定。固定章节默认不扩展，模板明确允许时才可增加子章节。正文作业独立冻结模板并检查哈希，改变模板用途或原件版本后必须重新规划。

风格原件按附件顺序单独保存为 `style-references/{index}/filename`，目录元数据用相对路径 `sample_paths` 保留主参考顺序。确认时从已冻结目录读取示例与 `style/profile.json`，验证逐文件内容哈希，再保存到作业的 `inputs/samples/` 和 `inputs/style/`。正文与恢复流程复用已确认风格，不重新分析出另一套结果；模板和风格示例均不放入业务研究的 `sources` 或 `knowledge` 快照。

目录确认视图直接显示完整目录树，支持滚动阅读全部节点。确认区有生成按钮、修改建议框、重新生成入口与可选风格说明；不再隐藏在强制模板或封面流程之后。Word 目录预览与最终文档使用同一份已冻结版式策略：有模板时沿用原件的结构与格式，无模板时采用主参考的可靠参数与明确格式要求，未规定部分保留默认样式。缺少 Office／PDF 转图组件时显示结构预览，不能把目录预览称为已生成正文。

目录预览的占位说明只表示正文尚未生成，不伪造业务待确认问题。恢复旧会话时，过期预览从保存的权威目录重新排版到独立缓存，不调用模型、不修改需求、目录版本或章节 ID，也不覆盖历史文件；PDF 和页面图片由新预览生成。

## 接口

| 接口 | 用途 |
| --- | --- |
| `POST /conversations` | 创建会话，可携带可选写作指南 |
| `GET /conversations` | 分页读取历史会话，置顶优先、组内按内容更新时间排序，返回名称及置顶状态 |
| `GET /conversations/{id}` | 恢复消息、资料、输入草稿、目录及任务 |
| `PATCH /conversations/{id}` | 更新 `title`（去除首尾空白后 1～200 字符）或 `pinned`；自定义名称不会被后续消息覆盖 |
| `DELETE /conversations/{id}` | 仅删除会话、消息、草稿与资料关联，保留文件；加 `?delete_files=true` 同时清理独占上传与任务文件，共用资源保留；不存在返回 404，处理尚未停止返回 409；前端确认后执行，删除当前会话后进入新建页面 |
| `POST /conversations/{id}/sources?filename=...` | 原始文件流上传并绑定会话 |
| `PATCH /conversations/{id}/sources/{source_id}` | 保存 `{role: "source" \| "template" \| "style_reference"}`；校验模板类型与数量，并使旧目录失效 |
| `DELETE /conversations/{id}/sources/{source_id}` | 移除本会话资料引用并使目录失效 |
| `PUT /conversations/{id}/draft` | 保存 `{text}`，不覆盖资料列表 |
| `PUT /conversations/{id}/writing-guide` | 后端保留的写作指南接口；更新时使旧目录失效，当前 GUI 无选择控件 |
| `POST /conversations/{id}/messages` | `{text, action, selection_revision?, advice?}`，返回 SSE |
| `GET /conversations/{id}/directories/{revision}/style` | 校验目录所属会话，查看该版本的 `style/style.md`；无风格说明返回 404 |
| `GET /conversations/{id}/styles/{revision}` | 校验会话归属及冻结原件，查看独立聊天分析生成的 `style.md`；无有效结果返回 404 |
| `POST /jobs/{id}/pause` / `resume` | 停止或继续属于指定会话的任务 |
| `GET` / `POST /jobs/{id}/confirmation` | 读取当前问题与版本；提交可选答复、幂等请求 ID 和本轮额度后续跑 |
| `GET /jobs/{id}/confirmations/{request_id}/artifact` | 下载对应续跑前归档的 Word |
| `GET /jobs/{id}/stream` | 实际任务事件与历史重播 |

上传响应含文件 `id/name/size/role` 与 `directory_invalidated`；用途修改响应含权威 `files` 列表和 `directory_invalidated`，同用途重复保存不撤销目录。删除响应含移除的 ID 及更新状态。兼容的低层上传和 Word 预览资源接口继续保留；模板用途通过文件 PATCH 设置，不经过旧模板库或预览推荐接口。

SSE 使用 `message.delta/completed/failed`、`directory.update/review`、`job.created`、`job.paused/resumed/failed`、`work.update` 和 `artifact.ready`。进度只反映实际阶段和已知耗时，不补造完成百分比；收到 HTTP 200 只表示流建立，不等于目录或正文成功。

普通聊天及意图判断只显示“正在思考…”等待动效，不展示步骤框或“下面显示当前步骤”的占位正文；收到非空白正文后隐藏动效并流式显示回答。目录研究、风格分析和正文生成才显示步骤框，位置在回复正文上方，避免被不断增长的答案向下推。普通聊天历史中的进度记录继续保留在后台，刷新时也不展示为任务。风格分析已完成后，准备解释和流式回复不会重新打开已结束的分析步骤或继续显示旧步骤正在执行。

目录研究的 `directory.update` 携带稳定的 `activity.id`、跟随界面语言的动作说明、当前状态、总耗时和当前步骤耗时。动作说明使用真实文件名、章节／Sheet／页与实际返回的结构数、原文字数，不把 `fs.inspect` 等工具名当作进度。每个新动作增加一条记录；同一动作的心跳和模型响应阶段只更新原行。模型传输通过任务隔离的活动订阅提供等待、连接、分析、接收结果四类状态，不传送原始 reasoning 或结构化 JSON，也不增加模型调用。生成完成后步骤折叠，失败时保留展开；处理记录保存在会话助手消息的 `activities` 中，刷新后仍能查看，但不会进入下一次聊天或意图判断的模型上下文。

界面请求使用 `Accept-Language`。后端 `api/localization.py` 在 JSON 和 SSE 的展示字段上应用 `locales/*.json` 中的中英对应，不修改保存的任务、用户资料或下载文件；完整 SSE 事件到达后立即转发，不等待整个任务结束。响应附带 `_translations`，前端在展示时读取对应文案，已收到的进度、诊断和错误也能随语言切换。用户消息、文件名、章节标题、引文、模型正文和流式回复保持原文；新的模型回复使用 `content_origin=model` 标记。遇到未登记的文字保留原文，不用通用提示掩盖信息。

文档输出语言与界面语言分别保存在 `JobInput.language` 和 `JobInput.ui_language`。正文、默认待填项、参考资料标签和文档下载后缀跟随写作要求；显式语言要求优先，界面设置只控制工作台及过程说明。新增固定提示需登记中英对应；代码注释、工具说明及模型提示词使用英文。中文输入识别规则、真实字体名、协议标识与历史证据原文保留，不能为翻译破坏旧任务的身份或内容校验。

风格分析使用 `style.update` 复用同一进度结构，界面标为“风格分析过程”。`style.completed` 提供状态、文件名、缓存命中和风格说明地址，随后仍可收到普通 `message.delta/completed` 答复。会话保存 `style_analyses` 记录，助手消息保存 `style_analysis` 结果及 `activity_label`；刷新可恢复结果卡，即使后续解释失败，已生成的说明仍可查看。该事件不改变目录预览、目录确认状态或正文生成阶段。

使用风格摘要的普通聊天回复也保存 `style_context_versions`，将回答绑定到实际提供的附件 ID 和内容哈希。进入下一次意图判断或回答前，程序核对当前用途、版本及本次选定范围；失效的旧风格回复在模型历史中替换为过期说明，原始会话记录仍保留供用户查看。结果卡、进度和版本元数据本身不重复送入模型。

## 持久化与任务控制

消息、需求原文及版本、资料引用、目录状态、作业关联与输入草稿保存在服务端工作空间，浏览器保存当前会话入口、尚未同步的文字草稿和面板尺寸等界面偏好。新建会话不删除旧数据；服务重启应继续使用同一个数据目录。

历史会话以单行标题展示，桌面悬停或键盘聚焦时显示省略号菜单与置顶按钮；触屏保留可直接操作的入口。菜单仅有重命名、置顶／取消置顶、仅删除对话、删除对话和文件四项。后一种删除按资源归属清理独占上传、历次目录／风格工作目录及文档任务；其他会话、任务引用的文件和全局共用预览、资料处理缓存保留。它不是工作空间全盘擦除操作。清理前检查路径及运行状态，普通文件操作失败时恢复原文件和会话记录。

前端以会话 ID 和视图版本隔离异步响应。切换会话可脱离当前 SSE 观察者，已经创建的文档任务继续执行。重新打开会话恢复服务端状态与进度；断线不会把后台失败或暂停误判成成功。

正文事件流先发送 `job.snapshot`，包含当前状态和可用交付信息。前端请求 `replay_history=false`：已结束和暂停任务直接通过快照恢复，不必等待历史日志回放完才显示下载信息；运行中的任务仍接收进度事件。历史进度不能覆盖最终状态，也不能在 `artifact.ready` 后重新启动等待动效。

发送及目录确认按钮在上传尚未完成、存在失败文件、资料正在移除或用途正在保存时禁用，避免对不完整输入启动任务。暂停保持会话锁定，明确继续后恢复同一作业。失败视图保留原因、阶段、相关章节、已保存进度和必要的安全诊断；原始请求、密钥和服务内部错误不会直接渲染到页面。

## 待确认补答与重新检查

待确认交付后，`ConfirmationPanel` 展示真实问题、相关章节、已用调用次数和答复框。用户可回答部分问题，或留空直接重试未完成检查；本轮调用额度默认200、允许1～10000，累计次数不清零且上限100000。来源批注另有“此答复已解决这条来源批注”复选框，只有用户明确勾选且修订成功提交后才关闭该批注，填写“不确定”等答复不会自动关闭。

未回答的业务问题保持待确认，不能因为模型复查时没有再次报告就消失；同一答案适用于多个关联问题时，可分别填写相同答复。技术与版式问题通过对应检查重建，空答复重试不代表批准业务结论。

提交携带 `revision` 和稳定 `request_id`；版本冲突保留输入并要求刷新，同一请求重试不重复增加额度。答复草稿、额度及请求 ID 按会话/作业隔离保存，切换页面不会让旧异步响应写入新会话。成功后重新订阅原作业事件，目录保持不变，只直接修订问题对应章节，再执行审阅和交付流程。

旧 Word 下载转向本轮归档路径；问题视图、会话恢复及交付事件都提供历史草稿列表，刷新后仍可访问先前版本。运行中的新文件不冒充旧草稿。业务证据范围、无答复技术重试和事务边界见[待确认补答与续跑设计](confirmation-and-resume.zh-CN.md)。

## 模型设置与验证

模型设置支持 OpenAI 兼容的生成模型及可选判断模型，各自填写 Base URL、API Key 和 Model。判断服务也支持 Jev 原生协议：填写完整 `/v1/systemone` 地址及服务商提供的模型名（如 `jev-latest`）。搜索服务可选择 Tavily 或 DeepSeek Search。可选服务必须当前配置测试成功并由用户明确勾选启用。密钥不回传、不写入浏览器存储，关闭弹窗清空输入框。

高级参数保留默认关闭的“当前生成模型支持图片输入”（`supports_image_input`），用于资料研究、风格分析等实际图像输入。它是能力声明，普通文本连接测试不能证明模型已识图。

“生成 Word 后由 Jev 逐页评分并优化排版”开关已移除。新生成任务不再调用 Jev 页面评分、图片自检或低分后的自动版式修改。正常字体、字号、标题、表格、来源标记、模板保护和分页流程继续执行；内容审阅和模板检查失败仍按原规则处理。Folio 不宣称这些检查等于页面审美验收，也不自动调用独立项目 DocPolish。

浏览器回归使用实际 Vue 构建产物与受控 API／SSE，覆盖多资料上传、用途保存与恢复、第二模板拒绝及失败回滚、队列与会话隔离、目录确认修改、暂停恢复和真实 DOCX 下载。模拟接口测试不代表模型业务质量已经验收，文件研究与生成质量另行验证。

历史任务中的页面评分、问题与预览记录继续按其原始状态展示，不重写为已通过。保留历史产物读取不表示当前生成流程仍执行页面评分。

## 耗时与 Token 统计口径

交付卡片的耗时取作业创建到最后终态更新的实际时间差（`updated_at - created_at`），包含等待、暂停和中断，不累加并行任务耗时，也不包含作业创建前的目录规划。旧记录缺少该值时，界面退回最早子任务开始到最晚子任务结束的时间区间。显示的 Token 总数汇总已有业务子任务用量记录，不等同于完整服务账单，可能不含这些记录之外的调用。完整审计还需结合 provider 事件、目录和会话日志。
